# 检测安全门控设计

## 1. 解决的问题

复原图在视觉上更清晰，不代表车辆和行人检测一定更好。ACDC 冻结检测器实验已经观察到：部分复原方法会降低 mAP50 或召回率。因此，展示链路不能只依据 PSNR、天气强度或不确定性决定输出，还要检查复原候选是否破坏了下游感知证据。

## 2. 当前决策流程

每张图或每一帧执行以下步骤：

1. FPRNet 生成直接复原图、不确定性图和退化估计。
2. 校准保真融合生成候选图。
3. 视频模式可先进行运动补偿时序稳定。
4. 同一个冻结 YOLOv8n 检测输入图与时序候选。
5. 按类别和 IoU 匹配输入参考目标与候选目标，综合目标保留、框位置和置信度变化计算 `0–1` 检测安全分数。
6. 时序候选分数不低于 `0.90` 时采用它；否则继续检测未经过时序融合的逐帧候选。
7. 逐帧候选分数不低于 `0.90` 时绕过时序融合采用它；仍不安全时才回退输入图。单图模式没有时序分支，仍是候选与输入二选一。

输入检测结果只是运行时参考证据，不是真值。若输入图没有检测到道路目标，门控不会以此否决候选中新出现的目标。

## 3. 可审计输出

页面显示：

- 检测安全分数；
- 输入参考目标保持率；
- 匹配参考目标数；
- 采用时序候选、逐帧候选或输入的最终选择；
- 视频中三种选择各自的累计帧数。

每次视频实验另外保存同名 MP4、JSON、CSV 和安全决策时间轴 PNG。JSON 保存设置、总体统计和逐帧记录；CSV 可直接导入 Excel。时间轴将安全分数与 `0.90` 阈值叠加，并用色带标记时序候选、逐帧候选和输入回退，用黑点标记实际门控评估、紫线标记场景切换。界面的“最近视频实验对比”从 JSON 自动汇总，不依赖人工抄写。

## 4. 当前边界

- 该门控能发现“复原后原有检测证据明显受损”，但不能证明输入检测框一定正确。
- 候选中新出现的目标可能是真正被复原揭示的目标，也可能是误检；没有标注时不能完全区分。
- 正式论文结论仍须在 ACDC 等带真值数据上比较 mAP、召回率和漏检率。
- 当前分层门控至少增加一次检测器推理；时序候选被拒绝时还会增加逐帧候选检测，属于安全优先模式，后续需研究检测间隔、目标跟踪和轻量检测器。

视频提供风险自适应调度实验：首次帧、场景切换、低安全余量或刚采用非时序路径时立即评估；仅在时序候选有较高安全余量时短暂复用决策。30 帧 ACDC 三轮顺序轮换实测中，自适应每轮相对逐帧模式少评估 4 次，但三轮均有 3 帧输出了逐帧基线会拒绝的候选，且平均 FPS 未提高，因此当前只作为消融选项，默认仍逐帧评估。

## 5. ACDC 验证集阈值探索

200 张 fog/rain 验证图的冻结评测结果表明：输入基线 mAP50 为 `0.2042`，未门控的校准融合候选为 `0.1235`。旧阈值 `0.70` 得到 `0.1784`，只能部分限制损失；阈值收紧到 `0.90` 后，采用候选 32 张、回退 168 张，mAP50 为 `0.2052`、Recall 为 `0.4376`。相对输入的配对 bootstrap 区间跨越 0，因此不能宣称显著提升，只能表述为“在当前验证集上基本消除复原造成的检测损失”。报告位于 `runs/acdc_benchmark/perception_guard/REPORT.md`。

## 6. 验收标准

- 参考目标完全丢失时必须回退输入。
- 同类框高度重合且置信度接近时应采用候选。
- 输入无参考目标时不得仅因为候选出现新目标而强制回退。
- 视频 JSON/CSV 的帧数、采用数和回退数必须与页面汇总一致。
- 视频三级计数之和必须等于处理帧数；逐帧候选只能在时序候选被拒绝后采用。
- 自适应和固定间隔模式必须报告相对逐帧基线的“候选风险漏判”数量，不得只报告速度收益。
- 关闭检测安全门控时可作为消融对照，不得伪造安全分数。
