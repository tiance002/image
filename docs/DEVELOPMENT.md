# VS Code 开发约定

## 1. 推荐扩展

- Python；
- Pylance；
- Ruff；
- YAML；
- Jupyter（仅用于探索，正式实验逻辑进入源码）。

扩展由开发者自行确认安装，项目不自动修改用户级 VS Code 设置。

## 2. 日常开发流程

1. 在项目根目录打开 VS Code；
2. 选择 `.venv` Python 解释器；
3. 修改代码后运行 `ruff check .`；
4. 运行 `pytest`；
5. 运行相关冒烟训练；
6. 使用新配置名启动正式实验；
7. 检查日志和固定样例，再提交代码。

## 3. 文件职责

- `configs/` 只存实验参数，不写业务逻辑；
- `src/saferestore/models/` 只存模型组件；
- `src/saferestore/losses/` 只存损失定义；
- `src/saferestore/data/` 负责读取与变换；
- 训练入口负责编排，不重复实现模型细节；
- 实验结果写入 `runs/`，不得手工修改原始指标文件。

## 4. 命名规范

实验名建议：

```text
YYYYMMDD_model_dataset_resolution_seed
```

例如：

```text
20261008_fprnet_raincity_256_s42
```

## 5. 实验完成检查表

- 配置已复制到输出目录；
- 记录代码版本；
- 记录环境与GPU；
- 保存最佳和最后权重；
- 保存训练曲线；
- 保存固定验证样例；
- 输出机器可读 JSON/CSV 指标；
- 记录失败或中断原因。

## 6. 研究纪律

- 不根据测试集调整权重和阈值；
- 不删除失败实验记录来美化结果；
- 不只展示成功样例；
- 不用不同检测阈值比较不同复原方法；
- 不把“视觉更好”直接表述为“更安全”；
- 所有安全性结论必须由明确指标支持。
