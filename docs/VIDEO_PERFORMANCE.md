# 视频性能与轻量化记录

## 当前实现

视频链路由四部分组成：FPRNet 复原、运动补偿时序稳定、检测安全门控、结果编码。时序稳定在低分辨率灰度图上估计 Farneback 光流，再把光流按坐标尺度放大到输出分辨率完成重映射。默认光流最大边为 320，最终复原图和检测图仍保持用户选择的输出分辨率。

每次实验还会生成安全决策时间轴 PNG。绘图发生在逐帧处理计时结束后，不计入表中的模型处理延迟；它用于审计安全分数、阈值、最终选择、门控触发点和场景切换。网页同时提供完整结果 ZIP，归档 MP4、JSON、CSV 和时间轴，并在 `manifest.json` 中记录文件角色、字节数和 SHA-256，便于完整搬运和核验一次实验。

## 无摄像头实时调度仿真

页面把用户选择的结果视频帧率同时作为虚拟传感器到帧频率。例如 25 FPS 对应 `40 ms` 单帧预算。系统记录每一帧从复原开始到检测结束的真实耗时，并报告 P50/P95 延迟、超过预算的帧数，再用单工作线程“处理器忙则丢弃新到帧”的低延迟策略进行离线调度仿真：

- `达到`：没有帧超过预算，也没有模拟丢帧；
- `边缘可达`：短序列中尚未丢帧，但已经存在超时帧；
- `未达到`：模拟流中会发生忙碌丢帧。

该结果用于在没有摄像头时评估实时可行性。输出 MP4 仍保留所有已处理帧，便于画质和安全决策对比；当前实现并不是已经接入摄像头或 RTSP 的在线服务。

检测安全门控采用三级选择：先评估运动补偿后的时序候选；若其不安全，再评估未经过时序融合的逐帧候选；两种候选都不能保留输入道路目标证据时，才回退输入帧。这样可区分“复原本身不安全”和“时序融合引入损伤”。门控支持以下调度模式：

- 每帧评估：每帧执行分层候选检测，安全优先。
- 风险自适应（实验）：首次帧、场景切换、低安全余量或非时序选择后立即复核；高安全余量时最多复用 2 帧，且周期性强制刷新。
- 每 2/3/5 帧评估：关键帧执行分层检测，中间帧沿用最近选择并在最终输出上运行一次检测。
- 关闭门控：每帧只检测复原候选，用于速度上限和消融对照。

## 640 最大边实测

命令：

```powershell
python scripts\benchmark_video_modes.py --frames 30 --max-side 640 --repeats 3
```

基准在同一进程内先预热复原、时序和检测路径，再执行 3 轮顺序轮换，降低固定执行次序带来的偏差。环境为 NVIDIA GeForce RTX 4060 Laptop GPU、PyTorch 2.13.0+cu126、CUDA 12.6、Python 3.12.7。当前数值为均值 ± 总体标准差：

| 模式 | FPS | 延迟 | 复原 | 时序 | 检测/门控 | 时序/逐帧/输入 | 风险漏判 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 每帧安全门控 | 9.91 ± 0.50 | 101.2 ± 5.3 ms | 26.2 ms | 42.9 ms | 32.0 ms | 9/0/21 | 0 |
| 风险自适应 | 9.83 ± 0.50 | 102.0 ± 5.0 ms | 29.0 ms | 42.3 ms | 30.6 ms | 12/0/18 | 3 |
| 每 3 帧门控 | 10.62 ± 0.24 | 94.2 ± 2.1 ms | 31.7 ms | 42.6 ms | 19.9 ms | 3/0/27 | 1 |
| 关闭门控 | 11.32 ± 0.32 | 88.4 ± 2.6 ms | 33.2 ms | 42.8 ms | 12.4 ms | 0/0/0 | 21 |

完整 JSON、CSV 和 Markdown 保存在 `runs/performance/video_modes/`。

## 混合精度验证

页面可选“复原 FP16 + 检测 FP32”的实验模式。CUDA autocast 仅作用于 FPRNet 复原网络；安全检测器始终使用 FP32，以减少精度变化影响门控决策。运行：

```powershell
python scripts\benchmark_precision.py --frames 30 --max-side 640
```

同一段 30 帧 ACDC 雾天序列的实测结果如下：

| 指标 | FP32 | 复原 FP16 / 检测 FP32 |
|---|---:|---:|
| FPS | 9.41 | 9.50 |
| 平均延迟 | 106.3 ms | 105.2 ms |
| 复原耗时 | 23.7 ms | 23.4 ms |
| 检测/门控耗时 | 35.8 ms | 35.1 ms |

两种精度的候选图 MAE 为 `0.0305/255`、PSNR 为 `63.28 dB`；30 帧门控最终选择完全一致，且没有出现 FP16 在 FP32 会回退时采用候选的情况。总体加速仅 `1.010x`，因此它目前用于轻量化实验和一致性审计，网页仍默认 FP32。完整结果保存在 `runs/performance/precision/`。

## 结论与边界

- 低分辨率光流已将时序模块从此前全分辨率实测约 64 ms 降至约 34–38 ms。
- 本次 30 帧中逐帧候选采用数为 0，说明这段雾天序列里的候选损伤并非只由时序融合造成；三级路径是安全兜底能力，不能据此宣称检测性能提升。
- “风险漏判”定义为某模式输出候选、而同帧逐帧安全基线会回退输入；这是冻结检测器一致性意义下的代理风险，不等同于真实事故风险。
- 风险自适应每轮少执行 4 次门控，但平均 FPS 没有优于逐帧模式，并在三轮中稳定产生 3 帧代理风险漏判；当前证据不支持把它设为默认。
- 每 3 帧门控平均快约 0.71 FPS，但三轮中稳定存在 1 帧代理风险漏判；固定间隔不能和逐帧门控视为同等安全。
- 30 帧结果用于当前工程性能定位；正式硬件报告仍应记录 GPU 型号、驱动、功耗并进行多次重复测量。
- 三轮标准差显示 GPU 频率和系统负载仍会影响结果；正式论文实验需要更多重复、固定功耗状态并报告置信区间。
- 网页默认采用每帧门控；自适应和固定间隔仅用于速度—安全消融。
- 混合精度当前未带来有意义的吞吐提升；在更长视频和不同 GPU 上完成复测前，不将其设为默认。
